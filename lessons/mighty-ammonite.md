Observed once. Phase 13's second run was initialized on the initial route after a planned governing-prose park. Its planning-stage work (carrying the first run's advice and capturing the approved plan) ran inside setup, and the run opened implementation directly. Command zero then refused at acceptance: "missing successful pre-acceptance orchestration stages: orchestration.planning". The repair was truthful but awkward: acceptance attempt 1 closed as an error, a planning stage was recorded after implementation to re-verify the captured plan, and acceptance attempt 2 proceeded.

Containment: the out-of-order stage is stated in the END block. Prevention candidate: when a fresh run resumes after a planned park, either open `orchestration.planning` around carry-advice and plan capture, or initialize the run on a continuation route that does not require planning. The resume resource could say which one applies.
