## Namespace candidate qualification pin

As of 2026-10-22, the namespace library/CLI candidate has local synthetic qualification through Phase7: exact typed file/directory operations and new bytes, frozen folders/snapshots, explicit filesystem export, coordinated library excision and root-bound CLI recovery. The reference LocalSession is caller-owned unprotected admission, not authentication/encryption; direct CAS writers must share the domain fence or remain offline/CAS-only. The persistent public demo emits an executable revision-correct command sequence with real new replacement bytes, empty directories, snapshots/export and distinct collision/stale refusals.

Available environment evidence is macOS arm64 on APFS and the standing Linux aarch64 lane (kernel7.0.14-linuxkit, Python3.12.12, SQLite3.50.4; actual pytest temp overlay, checkout fakeowner). Native APFS case aliases exercise inode-based export/lock disjointness. Linux's six Darwin-only parameter leaves across five test functions are not run there; independent Linux unsupported-platform refusals are asserted. Exact inspected wheel/sdist and source-rebuilt wheel hashes match across platforms, with isolated installed namespace smokes and pinned hatchling1.32.0. Package version remains0.1.1 and namespace additions remain unreleased. No tag, upload, remote publication or consumer repository adoption occurred.

Release acceptance still requires the maintainer's exact version/capability scope, persisted identifier disclosure and destination decision. Protected adapter/key/external-copy custody, native SQLite VFS fault coverage, device-cache/hardware power loss, physical erasure and live-store adoption are not established by these process/fault proofs. Keep those requirements explicit instead of treating API/test readiness as a released dependency or a protected deployment. This factual pin does not authorize release work or broaden grants.
