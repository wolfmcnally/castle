# Namespace environment conformance

As of 2026-10-22. This specification separates the delivered trusted unprotected reference environment from requirements for a protected deployment. A capability descriptor is a caller assertion, not authentication, encryption, key possession or evidence that a filesystem supplies the asserted properties. No protected adapter, hardware power-loss qualification or live-store conversion is delivered here.

## Authority and admission

The host authorizes the caller before any Castle open/read, then supplies an AuthorizedSession with exact namespace/CAS roots, protection-domain identity and the required property set. Names, paths, UUIDs, content hashes and snapshot IDs confer no access. Keep one lifetime coordinator per protection domain and take its admission fence before Castle's coordinator/CAS locks. Serialize all direct users of that domain, including maintenance and recovery. Cross-domain moves need external orchestration and have no distributed atomicity guarantee.

`castle.namespace_environment.LocalSession` is the Unix reference for caller-controlled unprotected stores. Initialization alone may create the external shared lock. Ordinary open requires it to exist; it is never unlinked. Nonblocking flock refuses a competing owner. The reference checks a regular single-link no-follow lock and its inode binding, synchronizes lock and parent, and invalidates inherited descriptors/session in fork children through one weak-owner module hook. All coordinators must independently agree on the same stable domain-lock path. This class does not discover other users, authenticate a principal, defend against an administrator replacing caller-owned roots, or turn two lock paths into one domain.

Existing direct CAS CLI writers and maintenance commands do not acquire this namespace fence. Use them on CAS-only stores or during an explicit exclusive offline handoff with no namespace owner; invoking them concurrently with an active namespace is unsupported. A new empty CAS needs its ordinary index rebuild before namespace admission. The namespace CLI creates neither missing CAS roots nor replacement authority on a typo. Protected initialization refuses this unprotected session; there is no downgrade.

Do not certify a protected deployment by ticking the local column. Retain the actual adapter, filesystem/mount, OS/kernel/architecture, Python/SQLite/VFS, flush behavior and key policy with independent negative controls. A platform's unrun test is not a passed test. Device-level erasure, snapshots/backups, detached copies and remote holders require separate evidence and authority.

## Consumer addressing and projections

Gate policy before constructing/opening a Castle handle. Namespace reads return a committed revision; a search index's last reconciled revision is separate and may lag. Derive search rows only from file members, excluding snapshot control objects unless the application intentionally indexes them as documents. Names are mutable presentation. Retain namespace ID, entry ID and exact CasID; for historical citations retain snapshot identity, captured revision and its current validated binding. Replacement preserves the entry ID while changing content; duplication creates fresh IDs sharing immutable bytes. Logical deletion removes current metadata, not retained historical content or CAS authority. Never infer GC or confidential excision permission from unreferenced durable residue.

Take backups under the same domain's exclusive admission, with namespace database/identity/generation, operation authority and CAS journal/objects/identity consistently captured. A database-only copy, derived index or independently timed root copy is not a supported coherent restore. Restore must independently validate exact binding/epoch/inventory and refuse missing or mixed authority. Excision may invalidate historical root bindings; retain only the explicitly approved recovery authority, not selected private plaintext as a convenience witness.

## Local input/output and limits

CLI request JSON is strictly UTF-8, closed and versioned, accepts whitespace/key order but refuses duplicate keys, negative zero, floats/exponents/nonfinite numbers and unknown fields. Mutation requests preserve namespace ID, exact CAS binding, expected revision and operation UUID. Save the original request. A lost response or failed response write is unknown: query status or retry that identical request; a new token is a new intent. An exit 74 response failure or exit 130 interrupt does not establish rollback. Typed namespace errors contain only code, namespace_id, operation_id, actual_revision and effect. Argument-parser usage errors are separate.

`--content CasID=FILE` or a mutually exclusive `--content-file` JSON object supplies immutable bytes lazily after retained-outcome handling. Input paths are caller-owned relative to invocation cwd. Safe regular-file capture checks descriptor/name identity, size and change timestamps; Castle then validates declared size/hash. Named missing/unreadable/nonregular/changed inputs refuse before reserving a token. A saved successful request can replay even if its source is gone. Capturing sources and folder mappings consumes memory, including all supplied payloads; request/tree/manifest bounds do not promise constant memory or bounded content size. Apply admission/resource policy in the host before accepting large inputs.

`DirectoryDestination` creates an absent private output root containing `snapshot.json` and a separate `tree/` with only declared members, preserving empty directories and a member literally named snapshot.json. Existing paths/links/collisions refuse. It anchors traversal to directory handles, writes exclusively with no-follow flags, verifies content bytes and directory bindings and synchronizes before a receipt. A failure may leave caller-owned partial output; no recursive cleanup, overwrite, external atomic-publication or physical-erasure claim is made. The trusted caller must maintain destination custody while the callback runs and decide how to retain or dispose of exported plaintext.

## Qualification and release boundary

The repository's retained CLI/namespace/hermeticity families own the synthetic consumer protocols, restart/concurrency/refusal proofs and armed network negative control. The disposable example is an automated workflow; its retained-workspace commands support later manual usability review. Exact local wheel and validated-sdist-to-rebuilt-wheel installation is separate from a source test run. Archive allowlists, hashes, build generator and external-environment import checks bind that evidence; neither upload nor a release decision follows automatically.

Version 0.2.1 includes the namespace additions. Record actual native and Linux test results and known Darwin-only cases as not run on Linux. A Linux lane, adapter or device requiring new access parks only that dependent qualification. The operator still owns version/release scope, tags/publication, live-data adoption, protected custody and manual UI/error/retry-window judgment.

Reference destination-choice errors (existing output, symlinked or nondirectory ancestors) refuse namespace-root-unsafe; genuine member I/O failures remain namespace-io-failed with partial caller-owned output preserved. Physical symlink-free ancestors are required. Opened ancestor inode checks enforce authority disjointness on case-insensitive filesystems too. Failed buffered response streams are closed to prevent a second interpreter-finalization flush from changing the unknown-response exit status.


## Plain privacy and publication limits

Publishing the code and documentation reveals formats, field names, hash formulas, retention rules and synthetic examples. It does not upload running stores. Inspected release packages contain the allowlisted source, documentation, tests/examples where applicable, metadata and license; they exclude user stores, private inputs, credentials and repository planning/execution records. Public Git source/history is broader than a package and requires its own disclosure inspection. Package SHA-256 values identify published archive bytes, not private user documents.

A running namespace keeps names, metadata, parent/child relationships, stable entry/snapshot/operation IDs, revisions and content references in its user-controlled database and manifests. CAS journals can retain source labels, original relative paths and observation times; namespace publication uses opaque namespace/operation/publication provenance instead of host upload paths. Equal content hashes can identify matching bytes across copies or confirm a guessed document. Mutable names do not hide a stable entry's history. Snapshots and retained retry records can preserve information no longer present in the live tree.

The seven-day retry deadline does not automatically delete anything: explicit expiry removes request/result/error/fingerprint payloads logically while keeping the operation UUID retired forever. Old SQLite pages and other retained content can still contain prior bytes. Logical entry deletion and snapshot-catalog deletion likewise imply neither garbage collection nor erasure. Completed coordinated excision retains only safe transition evidence for its own operation, not selected names/content IDs or a removed-selection fingerprint; retained unrelated history remains subject to the explicit selection/dependency contract.

Two unsalted root equality hashes survive excision private-intent disposal in SQL completion. They hash each original resolved path's canonical JSON string plus final newline; distinct predecessor/successor columns and identity joins preserve their roles. Someone who obtains these records can guess predictable paths offline or link equal paths. They provide neither authentication nor path secrecy. Original root locations must still come from the caller; a hash cannot route recovery. Source transport handles/paths are absent from canonical namespace requests/manifests, and session keys/credentials are never persisted or logged by this protocol.

The unprotected reference environment leaves store artifacts readable to processes with filesystem access. Authorized sessions govern API access but the reference class authenticates no person and encrypts no bytes. A protected deployment must separately qualify complete plaintext/key/session/backup/export custody. Caller-saved requests, source originals, shell history, exported plaintext, disconnected replicas, backups, filesystem snapshots and device residue are outside Castle's completed local cleanup claim. No release of this candidate authorizes live-store cleanup or claims physical erasure.


## Delete/Excise caller qualification

As of 2026-10-28, version 0.2.1 distinguishes live-only Delete from explicit managed-content/metadata Excise. Historical inventory and closure preview are authorized reads, not access grants or purge authorization. They expose retained names, metadata, dependency relationships and hashes to the caller; protect saved output. Queries perform exclusive full-store validation. Complete finite collection/member/byte limits refuse overflow without partial results; payload-free retired UUID reservations do not accumulate as inventory owners. A rejected operation can change closure at an unchanged revision, so refresh preview after dependency-conflict as well as revision-conflict. Conservative conflict IDs may identify innocent equal strings in retained journal/remotes fields; never treat that match as automatic authority to delete unrelated bytes.

The explicit selection must include intended content identities, shared live/deleted entry owners, disclosing operation payloads and all retained snapshot actions. Delete keeps bytes/logging; Excise removes selected logical payloads and owned managed files using the existing successor epoch and fresh namespace generation. Content-free directory/name/metadata cleanup also moves the epoch. Permanent opaque UUID reservations and selection-free completion/root-equality hashes remain; no name, parent, size, selected content identity or removed-selection fingerprint is retained in that transition evidence. An explicit file-content selection is required to purge bytes as well as entry metadata. Filesystem/device residue, external inputs/exports/backups/replicas, physical media overwriting, protected adapter custody and hardware power loss remain outside the local claim.

The operator directly approved a full tagged release of these improvements. That scoped publication authority does not authorize live-store cleanup or downstream adoption. Native/Linux fault, process-loss, concurrency and installed-artifact checks must be recorded against final bytes; the release page records actual publication. Manual usability remains an operator judgment.
